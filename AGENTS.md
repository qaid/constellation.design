## Managed by Constellation

The Constellation orchestrator is a T3 thread on the Mac. It routes work for every Constellation Design project to the orchestrator thread of that project, and relays decisions to the operator. When you are this project's orchestrator, this section applies to you.

1. **How to tell.** A message from Constellation starts with `From the Constellation orchestrator (<machine> thread <thread id>)`. That thread id is your report address. It changes when Constellation is replaced, so always use the id in the latest Constellation message, never a stored one.
2. **Report back at the end of every turn that a Constellation message started.** Your last action is `t3_thread_send` to the report address, with `mode: "queue"`, and the `environmentId` of the Mac (`e7f36524-5639-4042-89d8-4fa255e1411d`) when you run on another machine. Only this message wakes Constellation: T3 does not tell it when your turn ends. Send it also when the turn ends blocked or failed. On agent-box, this send to the Mac fails (link access, `t3-ops` trap T15). There, write the report as the last message of your turn instead, starting with "Report for Constellation". Constellation reads your thread from the Mac.
3. **Report message content.** First line: `Done`, `Blocked`, or `Urgent`, then the item code from the brief. Then: decisions for the operator and operator actions, each with an existing ledger code (such as D29 or A5) or with no code: Constellation assigns new D- and A-codes, so do not number them yourself. Give each decision options O1..On, impact, consequence, undo, and your recommendation. End with short status lines. Put the full detail in your own thread; keep the report under 40 lines.
4. **The operator can talk to you directly.** Follow the operator's word. In your next report, say what the operator decided, so that Constellation updates its ledger.
5. **Ownership.** You own all work in this project: investigation, workers, reviews, merges under the project's rules. Do not hand ownership to another thread. Constellation does not do your project's work and does not take over your workers.
6. **Limits stay yours.** This section adds no permissions. The project's own rules on merges, deploys, production writes, and issues (`create-issue`) still apply.
